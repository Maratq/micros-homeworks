## Задача 3: API Gateway * (необязательная)

### Есть три сервиса:

**minio**
- хранит загруженные файлы в бакете images,
- S3 протокол,

**uploader**
- принимает файл, если картинка сжимает и загружает его в minio,
- POST /v1/upload,

**security**
- регистрация пользователя POST /v1/user,
- получение информации о пользователе GET /v1/user,
- логин пользователя POST /v1/token,
- проверка токена GET /v1/token/validation.

### Необходимо воспользоваться любым балансировщиком и сделать API Gateway:

**POST /v1/register**
1. Анонимный доступ.
2. Запрос направляется в сервис security POST /v1/user.

**POST /v1/token**
1. Анонимный доступ.
2. Запрос направляется в сервис security POST /v1/token.

**GET /v1/user**
1. Проверка токена. Токен ожидается в заголовке Authorization. Токен проверяется через вызов сервиса security GET /v1/token/validation/.
2. Запрос направляется в сервис security GET /v1/user.

**POST /v1/upload**
1. Проверка токена. Токен ожидается в заголовке Authorization. Токен проверяется через вызов сервиса security GET /v1/token/validation/.
2. Запрос направляется в сервис uploader POST /v1/upload.

**GET /v1/user/{image}**
1. Проверка токена. Токен ожидается в заголовке Authorization. Токен проверяется через вызов сервиса security GET /v1/token/validation/.
2. Запрос направляется в сервис minio GET /images/{image}.

## Задача 1: API Gateway - ответ

# Сравнение решений для API Gateway

Для реализации API Gateway, который будет маршрутизировать запросы, проверять аутентификацию и обеспечивать HTTPS-шифрование, стоит рассмотреть несколько популярных решений. Для удобства ниже представлена сравнительная таблица их возможностей, а также аргументация выбора оптимального варианта.

## Сравнительная таблица возможностей API Gateway

| Решение               | Маршрутизация запросов | Аутентификация и авторизация | Терминация HTTPS | Масштабируемость | Простота интеграции |
|-----------------------|------------------------|------------------------------|------------------|------------------|---------------------|
| **Kong**             | Да                    | JWT, API-ключи, OAuth        | Да               | Высокая          | Хорошая             |
| **NGINX**            | Да                    | Возможна через плагины       | Да               | Высокая          | Средняя             |
| **Amazon API Gateway**| Да                    | Интеграция с AWS IAM, OAuth  | Да               | Высокая          | Отличная (в рамках AWS) |
| **Apigee (Google)**  | Да                    | Различные механизмы          | Да               | Высокая          | Хорошая             |
| **Spring Cloud Gateway**| Да                  | Пользовательская реализация через экосистему Spring | Да | Высокая      | Хорошая             |
| **Envoy Gateway**     | Да                    | Интеграция с Service Mesh    | Да               | Высокая          | Средняя             |

## Обоснование выбора

На основе анализа таблицы, оптимальным решением для реализации API Gateway является **Amazon API Gateway**. Вот почему:

1. **Гибкая маршрутизация запросов.** Это решение отлично обрабатывает как REST, так и WebSocket API, позволяя удобно настраивать маршруты в зависимости от потребностей.
   
2. **Поддержка аутентификации и авторизации.** Amazon API Gateway напрямую интегрируется с AWS IAM, что позволяет централизованно управлять доступом, а также поддерживает OAuth и другие распространенные механизмы для проверки запросов.

3. **Терминация HTTPS.** Gateway позволяет легко настроить HTTPS-шифрование, включая создание и использование SSL-сертификатов, что обеспечивает высокий уровень безопасности соединений.

4. **Масштабируемость.** Как часть AWS, этот инструмент автоматически адаптируется к нагрузке, что делает его удобным для систем с быстро меняющимися потребностями.

5. **Простота интеграции.** В рамках экосистемы AWS настройка Amazon API Gateway максимально упрощена, что позволяет быстро начинать работу без лишних сложностей.

## Задача 2: Брокер сообщений - ответ

Для выбора подходящего брокера сообщений, который соответствует заданным требованиям, был выполнен анализ популярных решений: Apache Kafka, RabbitMQ и ActiveMQ. Результаты собраны в таблице, а ниже приведены аргументы в пользу выбранного варианта.

## Сравнительная таблица возможностей брокеров сообщений

| Брокер       | Кластеризация       | Хранение сообщений   | Скорость работы          | Форматы сообщений           | Разделение прав доступа | Простота эксплуатации |
|--------------|---------------------|----------------------|--------------------------|-----------------------------|-------------------------|-----------------------|
| **Apache Kafka** | Да, с репликацией | Да, на диске         | Очень высокая            | JSON, Avro, Protobuf и др.  | Да                     | Средняя              |
| **RabbitMQ** | Да, поддержка кластеров | Да, на диске или в памяти | Высокая                  | Текстовые, двоичные, XML и др. | Да                     | Высокая              |
| **ActiveMQ** | Да, с кластеризацией | Да, через KahaDB или JDBC | Средняя                 | Текстовые, двоичные и др.    | Да                     | Средняя              |

## Обоснование выбора

На основе сравнения оптимальным решением является **RabbitMQ**. Вот почему:

1. **Простота эксплуатации.** RabbitMQ отличается удобным интерфейсом для настройки и управления. Он поддерживает множество языков программирования, что делает его универсальным и легким в освоении.

2. **Гибкость форматов сообщений.** RabbitMQ работает с текстовыми, двоичными, XML и другими форматами сообщений, что делает его подходящим для различных сценариев использования.

3. **Скорость и производительность.** RabbitMQ обеспечивает высокую скорость работы, особенно в средах с умеренной или высокой нагрузкой. Он хорошо справляется с задачами, где важна быстрая доставка сообщений.

4. **Кластеризация и отказоустойчивость.** Поддержка кластеров и репликации данных позволяет RabbitMQ оставаться стабильным даже при сбоях.

5. **Надежность хранения и безопасность.** RabbitMQ хранит сообщения на диске, что предотвращает их потерю. Также он включает встроенные механизмы для разделения прав доступа к различным потокам сообщений.

Таким образом, **RabbitMQ** идеально подходит для систем, где важны простота настройки, надежность, высокая скорость работы и гибкость в обработке сообщений.

 RabbitMQ идеально подходит для систем, где важны простота настройки, надежность, высокая скорость работы и гибкость в обработке сообщений.
